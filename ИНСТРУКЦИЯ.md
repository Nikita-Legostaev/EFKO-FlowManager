## 1. Баг «выбираю Майонез — обрабатывается Масло»

**Причина.** В `process_file` имя CSV собирается только из имени исходного
xlsx и не содержит категорию. После прогона «Масло» файлы уже лежат в папке и
свежее исходников, поэтому при смене категории срабатывает проверка
«Пропущен (уже обработан)» и в папке остаются старые данные по маслу.
В логе это видно строками `Пропущен (уже обработан): …`.

Выбран вариант B — имена CSV не меняем (Power Query править не надо), но
папка очищается при смене категории.

### 1.1. `promodate_functions.py` — добавить хелпер

Вставьте перед функцией `def process_file(` (то есть сразу после
`def get_first_sheet_name(...)`):

```python
CATEGORY_MARKER = "_last_category.txt"


def _read_last_category(output_folder: str) -> str:
    path = os.path.join(output_folder, CATEGORY_MARKER)
    try:
        if os.path.isfile(path):
            with open(path, encoding="utf-8") as f:
                return f.read().strip()
    except Exception:
        pass
    return ""


def _write_last_category(output_folder: str, cat_name: str):
    try:
        os.makedirs(output_folder, exist_ok=True)
        with open(os.path.join(output_folder, CATEGORY_MARKER), "w", encoding="utf-8") as f:
            f.write(cat_name)
    except Exception as e:
        logging.error(f"[promodate] не удалось записать {CATEGORY_MARKER}: {e}")


def _reset_output_if_category_changed(output_folder: str, cat_name: str, log) -> bool:
    """
    Если предыдущий прогон был по другой категории — удаляет старые CSV.

    Без этого process_file() посчитает уже лежащие файлы «обработанными»
    и оставит в папке данные предыдущей категории.
    Возвращает True, если чистка выполнялась.
    """
    os.makedirs(output_folder, exist_ok=True)
    prev = _read_last_category(output_folder)

    if prev and prev != cat_name:
        removed = 0
        for f in os.listdir(output_folder):
            if not f.lower().endswith(".csv"):
                continue
            try:
                os.remove(os.path.join(output_folder, f))
                removed += 1
            except Exception as e:
                log(f"⚠ Не удалось удалить {f}: {e}")
        log(f"🔄 Категория сменилась: «{prev}» → «{cat_name}». Удалено старых CSV: {removed}")
        _write_last_category(output_folder, cat_name)
        return True

    if not prev:
        log(f"ℹ Категория обработки: «{cat_name}» (первый прогон в этой папке)")
    else:
        log(f"ℹ Категория обработки: «{cat_name}» — совпадает с предыдущей, "
            f"уже готовые CSV пропускаются")
    _write_last_category(output_folder, cat_name)
    return False
```

## 2. Кнопка «Сделать CSV» на главном экране

Нужна отдельная кнопка, которая делает **только обработку**: берёт уже
скачанные xlsx из папки «Скаченное», фильтрует по категории и сетям и
складывает CSV в папку сохранения. Без FTP, без Power Query, без макросов.

Сейчас такого варианта нет: «▶ Запустить» в режиме «Запустить всё» тянет
полный пайплайн вместе с Excel, а отдельные стадии — это только Query/макросы.

### 2.1. `api_scheduler.py` — метод обработки

Добавьте в класс `ApiSchedulerMixin` рядом с `start_download` / `start_process`:

```python
    def start_process_csv(self, p):
        """
        Только обработка: xlsx из «Скаченное» → CSV в папку сохранения.
        Без скачивания с FTP, без Power Query и без макросов.
        """
        self._stop_event.clear()

        def _worker():
            try:
                process_files_thread(
                    _SV(p.get("output_folder")),
                    _SV(p.get("category")),
                    FILTER_OPTIONS,
                    self._log,
                    self._mb,
                    self._stop_event,
                    lambda *a, **kw: None,   # Power Query намеренно не трогаем
                    _SV(""),
                    _SV(""),
                    "",
                    "",
                    progress_callback=self._progress,
                    set_title=self._set_title,
                    networks=p.get("networks") or None,
                )
            except Exception as e:
                self._log(f"⚠️ Ошибка обработки: {e}")
            self._emit("done")

        threading.Thread(target=_worker, daemon=True).start()
        return True
```

Заглушка вместо `refresh_power_query_files` — это то, что отличает кнопку от
полного пайплайна: `process_files_thread` в конце сама дёргает обновление
Power Query, здесь оно подменяется пустышкой.

Фикс из раздела 1 работает и здесь: при смене категории папка очистится
перед обработкой.

## 3. Автообновление у пользователей

Механизм уже был, файл `updater.py` в комплекте — это его исправленная версия.
Что чинится: путь к `version.txt` (раньше при запуске из исходников он искался
в папке Python), запись версии до фактической подмены exe, отсутствие ручной
проверки и обновление только exe без `web/`.

### 3.1. Раскладка на сетевом диске

В папке
`V:\…\Полочные цены Promodata\EFKO-FlowManager\` держите:

```
version.json
EFKO-FlowManager_3.1.0.exe      ← имя с версией!
web\                            ← если менялся интерфейс
(скрипты парсинга и parsers.json едут внутри exe — отдельно не выкладываются)
```

`version.json`:

```json
{
  "version": "3.1.0",
  "exe": "EFKO-FlowManager_3.1.0.exe",
  "notes": "Фикс смены категории, полный цикл с главного экрана, вкладка Парсинг",
  "files": ["web"]
}
```

**Почему exe с версией в имени.** Если перезаписывать один и тот же
`EFKO-FlowManager.exe`, вы ломаете файл ровно в тот момент, когда кто-то его
запускает или копирует. С версионированным именем старые копии продолжают
работать, а откат — это правка одной строки в json.

### 3.2. Порядок выкладки новой версии

1. Собрать exe, переименовать в `EFKO-FlowManager_X.Y.Z.exe`.
2. Скопировать его на V:.
3. Обновить `web/`, если менялся интерфейс.
4. **Последним** шагом обновить `version.json`.

Порядок важен: пока json указывает на старую версию, никто не начнёт
скачивать наполовину залитый exe.

Допишите **в конец файла**:

```javascript
// ══════════════════════════════════════════════════════════════════════
// ОБНОВЛЕНИЯ
// ══════════════════════════════════════════════════════════════════════
async function checkUpdates(silent) {
  const label = document.getElementById('update-label');
  const icon  = document.getElementById('update-icon');
  if (label && !silent) label.textContent = 'Проверяю…';
  try {
    const info = await pywebview.api.check_updates_manual();
    if (!info.ok) {
      if (!silent) showToast('warning', info.msg || 'Папка обновлений недоступна');
      if (label) label.textContent = 'Проверить обновления';
      return;
    }
    if (!info.available) {
      if (!silent) showToast('success', `Установлена последняя версия (${info.current})`);
      if (label) label.textContent = `Версия ${info.current}`;
      if (icon) icon.textContent = '✅';
      return;
    }
    onUpdateAvailable(info);
  } catch (e) {
    if (!silent) showToast('error', 'Ошибка проверки обновлений');
    if (label) label.textContent = 'Проверить обновления';
  }
}

function onUpdateAvailable(info) {
  const label = document.getElementById('update-label');
  const icon  = document.getElementById('update-icon');
  if (label) label.textContent = `Обновить до ${info.remote}`;
  if (icon)  icon.textContent = '🆕';

  const text =
    `Доступна новая версия ${info.remote} (у вас ${info.current}).\n\n` +
    (info.notes ? `Что нового:\n${info.notes}\n\n` : '') +
    `Обновить сейчас? Приложение закроется и запустится заново.`;
  if (!confirm(text)) return;

  pywebview.api.install_update_now().then(res => {
    if (!res.ok) showToast('error', res.msg || 'Не удалось обновиться');
  });
}

// Уведомление из фоновой проверки при старте
(function () {
  const prev = window.__pyEvent;
  window.__pyEvent = function (payload) {
    if (payload.type === 'update_available') { onUpdateAvailable(payload.data); return; }
    prev(payload);
  };
})();
```

## 4. Вкладка «Парсинг ЖДСК»

**Схема.** Скрипты парсинга и реестр `parsers.json` лежат внутри проекта, в
папке `parsing/`, и попадают в сборку — значит, раздаются и обновляются вместе
с приложением. Результаты (Excel по каждой сети) пишутся в папку, которую
пользователь выбирает во вкладке. На сетевой диск парсинг не пишет ничего.

**Как это работает.** Скрипты не переписываются — они остаются обычными
самостоятельными файлами. Приложение запускает их через `runpy`, подставляя
рабочей папкой папку результатов: всё, что скрипт пишет «рядом с собой»,
оказывается там. При первом запуске в папку результатов копируются
вспомогательные исходники из сборки (`towns.csv`,
`city_and_regions_Russia.xlsx` и прочие) — иначе скрипт их не найдёт.
Уже существующие файлы не перезаписываются, поэтому накопленные кэши и
чекпоинты (`bristol_checkpoint.json`, `fixprice_cache.json`) сохраняются и
ускоряют повторный прогон.

## Порядок внедрения и проверка

1. **Фикс категории** (раздел 1) — он ломает данные прямо сейчас, ставить первым.
   Проверка: прогон «Масло» → «Майонез», в логе `🔄 Категория сменилась`.
2. **Кнопка «Сделать CSV»** (раздел 2). Проверка: после скачивания жмём
   кнопку, в логе идёт обработка, Excel не запускается.
3. **Апдейтер** (раздел 3). Проверка: положить на V: `version.json` с версией
   выше локальной → при старте появляется предложение обновиться; кнопка
   «Проверить обновления» работает и без перезапуска.
4. **Вкладка парсинга** (раздел 4). Проверка: `parsers.json` на V:, вкладка
   показывает список, «?» открывает инструкцию, 🔑 сохраняет ключ 2ГИС,
   «▶» на лёгкой сети (Скидкино или Смарт) отрабатывает и пишет в общий лог.

## Что стоит проверить руками

- **Парсеры под собранным exe.** `runpy` выполнит скрипт, но библиотеки
  берутся из сборки. Соберите тестовый exe и прогоните одну сеть — если упадёт
  на `ModuleNotFoundError`, допишите модуль в `hiddenimports` (раздел 4.2).
- **Кнопка «Стоп» на парсинге.** Она останавливает очередь между сетями, но не
  прерывает уже запущенный скрипт — так работает `runpy`. Если нужно жёсткое
  прерывание, парсеры надо переводить на запуск отдельным процессом; скажите,
  сделаю.
- **Ключ 2ГИС.** Во встроенном коде `monetka.py` зашит демо-ключ как запасной
  вариант. Пока свой ключ не сохранён, парсер будет работать на нём — с
  сильно заниженными цифрами по крупным регионам. Стоит получить рабочий ключ
  и вбить его через 🔑, иначе данные вводят в заблуждение.
- **Первый запуск у пользователя.** Пока папка результатов не выбрана, кнопки
  запуска ругаются и ничего не делают — это осознанно, чтобы файлы не улетели
  в случайное место. Стоит на словах договориться об общей папке, иначе у всех
  будут свои и данные разойдутся.
