# EFKO FlowManager

Настольное приложение отдела ОАР: скачивание и обработка промодаты, обновление
отчётов через Power Query, Nielsen, производство, сравнение цен, отчёты без OOS
и парсинг сайтов сетей.

Windows, Python + [pywebview](https://pywebview.flowrl.com/) (интерфейс — обычные
HTML/CSS/JS внутри окна WebView2), сборка в один каталог через PyInstaller.

---

## Как это устроено

```

  │
  ├── app/              оболочка приложения
  │     window.py         создание окна pywebview, прогрев тяжёлых модулей
  │     orphans.py        зачистка зависших процессов Excel до старта
  │
  ├── api/              всё, что вызывается из JS через pywebview.api.*
  │     core.py           Api-ядро: события в UI, конфиг, диалоги, _run_bg
  │     promodate.py      режимы промодаты (ЦО / Мониторинг / Дополнительно)
  │     scheduler.py      планировщик, Windows Task Scheduler, запуск промодаты
  │     competitors.py    конкуренты, Nielsen, обновление квери, доли рынка
  │     production.py     производство, SKU-матчер
  │     price.py          сравнение цен Купер vs PromoData

  │     parsing.py        вкладка «Парсинг ЖДСК»
  │
  ├── services/         вся предметная логика, без знания об интерфейсе
  │     promodate.py      FTP, обработка xlsx → CSV, Power Query, макросы
  │     competitors.py    обновление файлов через query (win32com)
  │     nielsen.py        обработка выгрузок Nielsen
  │     production.py     свод производства (СВОД, НПК, Тольятти)
  │     price_comparison.py
  │     oos.py, oos_ketchup.py
  │     sku_matcher.py    сопоставление SKU (TF-IDF / классический режим)
  │     scheduler.py      расписание запусков
  │     parsing_runner.py движок вкладки парсинга
  │
  ├── core/             инфраструктура
  │     paths.py          где искать ресурсы (исходники / собранный exe)
  │     config.py         config.json: загрузка, слияние, сохранение
  │     logging.py        настройка логов
  │

```

Слои разделены строго: `services/` ничего не знает про pywebview и получает
`log`/`stop_event` параметрами, `api/` только связывает интерфейс с сервисами.

### Api собирается из миксинов

`api/__init__.py` склеивает `Api` из миксинов по вкладкам. Каждый публичный
метод такого миксина автоматически доступен в JS как `pywebview.api.<имя>()`.

### Фоновые операции: `_run_bg`

Любая долгая операция обязана запускаться через `self._run_bg(...)` из
`api/core.py`. Обёртка берёт на себя то, что раньше писали руками в каждом
методе и регулярно забывали:

* `try/except` вокруг работы — иначе исключение убивает поток молча, а
  интерфейс навсегда остаётся с крутящимся прогрессом и заголовком «⏳ …»;
* `finally` — заголовок и прогресс сбрасываются, чем бы дело ни кончилось;
* блокировка занятости — вторая операция не стартует поверх первой (почти все
  гоняют Excel через COM, а `_stop_event` один на всё приложение).

```python
def run_something(self, p):
    def _w():
        do_the_work(p["file"], self._log, self._stop_event)
    self._run_bg("⏳ Что-то делаю…", _w, name="Что-то")
    return True
```

### Остановка

Кнопка «Стоп» ставит общий `self._stop_event`. Сервисы обязаны проверять его в
своих циклах — прервать одну операцию Excel COM посреди выполнения нельзя,
поэтому проверки стоят на границах шагов. Скриптам парсинга событие
прокидывается через `runpy.run_path(init_globals={"STOP_EVENT": ...})`, они
читают его как `STOP_EVENT` и проверяют в главных циклах.

### Где искать файлы в собранном приложении

`core/paths.py::_resource()` сначала смотрит рядом с exe, потом в `_internal/`
(туда PyInstaller кладёт `datas`). Порядок важен: обновление докладывает файлы
рядом с exe, и они должны иметь приоритет. `config.json` открывается с
`writable=True` — он всегда рядом с exe, иначе настройки стирались бы при
каждом обновлении вместе с `_internal/`.

## Разработка

```bash
pip install -r requirements.txt
python main.py
```

Тесты (покрывают слой `services/`):

```bash
python -m pytest test/ -q
```

Часть тестов падает вне Windows: они мокают `win32com`/`pythoncom`. См.
«Известные проблемы».

## Сборка

```bash
pyinstaller EFKO-FlowManager.spec
```

Результат — `dist/EFKO-FlowManager/`. Спека дополнительно копирует `web/`
рядом с exe: интерфейс можно править прямо в сборке, без пересборки.

Библиотеки, которые нужны только скриптам парсинга, PyInstaller статически не
видит — они запускаются через `runpy`. Такие библиотеки перечислены в `_optional`
в спеке и обязаны быть в `requirements.txt`, иначе в сборку не попадут.

## Выкладка обновления

На сетевом диске держите `version.json`, exe с версией в имени и, если менялся
интерфейс, папку `web/`:

```json
{
  "version": "3.1.0",
  "exe": "EFKO-FlowManager_3.1.0.exe",
  "notes": "Что изменилось",
  "files": ["web"]
}
```

`version.json` обновляйте **последним** — пока он указывает на старую версию,
никто не начнёт качать наполовину залитый exe. Имя exe с версией нужно, чтобы
не перезаписывать файл, который в этот момент у кого-то запущен.

## Известные проблемы

* **Тесты.** В `test/test_app.py` 9 имён классов дублируются — Python оставляет
  только последнее определение, поэтому 48 из 110 тест-методов никогда не
  выполняются. Ещё 27 падают: они мокают `services.*.pythoncom` / `.pl` /
  `.openpyxl`, а эти импорты давно перенесены внутрь функций ради скорости
  старта, и модульных атрибутов с такими именами больше нет.
* **Парсинг и Chromium.** Fix Price, Доброцен и Бристоль подключаются к
  системному Chrome/Edge по CDP (порт 9222), который приложение поднимает само.
  Отдельный Chromium от Playwright не нужен — в корпоративной сети он всё равно
  не скачивается.
* **`scripts/`** — черновики, в приложении не используются.
